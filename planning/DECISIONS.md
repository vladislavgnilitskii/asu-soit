## 2026-07-02 — Этап 0: Стабилизация

### D-004. Fail-fast на небезопасные секреты в production
`config.Load` завершает процесс (`log.Fatal`), если `APP_ENV=production`, а
`JWT_SECRET`/`DB_PASSWORD` пустые или равны дефолтным значениям для разработки.
**Почему:** нельзя случайно поднять прод с общеизвестными dev-секретами. В
development дефолты сохраняются — удобно для локального запуска.

### D-003. Клиенты-организации временно отклоняются (HTTP 501)
`POST /clients` с `client_type=organization` возвращает 501. Раньше код молча
создавал строку в `clients` без строки в `organizations` (orphan, нарушение
целостности).
**Почему:** полноценная поддержка организаций требует полей `name/inn/kpp` в DTO
и записи в `organizations` — это отдельная задача (новый функционал). До неё
честный отказ безопаснее порчи данных. **Следующий шаг:** реализовать организации
в рамках этапа «Клиенты и устройства».

### D-002. Автор изменения статуса — строго из JWT
`employee_id` для `request_status_history.changed_by` берётся из claims JWT
(`c.GetString("employee_id")`), а не из заголовка `X-Employee-ID`.
**Почему:** заголовок задаёт клиент — это позволяло подделать чужого автора
(spoofing/IDOR). Источник истины — только подписанный токен.

### D-001. Матрица ролей (RBAC) для текущих эндпоинтов
Согласовано с пользователем:

| Эндпоинт | Роли |
|---|---|
| `POST /clients` | admin, manager |
| `GET /clients`, `GET /clients/:id` | любой авторизованный |
| `POST /requests` | admin, manager |
| `PATCH /requests/:id/status` | admin, manager, engineer |
| `GET /requests`, `GET /requests/:id` | любой авторизованный |

**Почему:** приёмку (клиенты, создание заявок) ведут admin/manager; смену статуса
ремонта — те, кто им занимается (+ engineer). Роли `storekeeper`/`accountant`/
`sysadmin` получат доступ при появлении своих модулей (склад/финансы/админка).

### D-000. Миграция 009 (индексы) подготовлена, но не применена
`db/migrations/009_optimize_indexes.sql` удаляет дубли-индексы и добавляет
индексы на FK. **К живой БД не применялась** — применение = изменение схемы,
требует явного подтверждения пользователя (правило CLAUDE.md).
